How the tree is constructed: During Servo's box tree build in traverse_element(), when layout encounters an <svg> element, it extracts the SVG subtree from the DOM, resolves each element's type and geometry from DOM attributes, and attaches Arc<ComputedValues> from Stylo. The engine receives a self-contained tree — no DOM access needed.

⚠️ Error Handling

SvgEngineError — categorized by severity:

Error Variant Severity Example Engine Behavior
InvalidPathData(String) Recoverable Malformed `d` attribute on <path> Skip element, continue siblings
MissingReference(String) Recoverable fill="url(#missing)" with no matching id Treat as fill="none", continue
CircularReference Recoverable <use> referencing an ancestor that contains itself Break cycle, stop resolution
InvalidViewBox(String) Recoverable viewBox="abc" Treat as no viewBox, use default identity transform
InvalidLength(String) Recoverable Unparseable length value Use default (0 or 100%), continue
PaintServerError(String) Recoverable Gradient with no <stop> children Treat as transparent, continue

Error propagation: All recoverable errors produce partial output. The engine paints what it can and logs warnings. Fatal errors (unexpected internal invariants) propagate to the layout thread and produce a broken-image icon.

⚡ Threading Model & Lifecycle

Threading

Layout Thread (single thread):
  make_fragments() {
    SVG_ENGINE.process(root, viewport, dpr)
      ├─ StyleResolver.resolve()     ← sync
      ├─ LayoutEngine.compute()      ← sync
      ├─ PaintBuilder.build()        ← sync
      └─ return SvgDisplayList
  }
  → Convert → Vec<Fragment>
  → Return to box tree builder

The engine is entirely synchronous on the Layout Thread. No async bridges, no image cache round-trips, no cross-thread communication.

Lifecycle (Page Load)

1. update_the_rendering() fires reflow()
2. traverse_element() encounters <svg>
   → SvgStyledNode constructed
3. Contents::for_element()
   → ReplacedContentKind::SVGElement
4. svg_kind_size() → natural sizes
5. make_fragments():
   SVG_ENGINE.process()
   a. StyleResolver.resolve()   — walk 1
   b. LayoutEngine.compute()    — walk 2
   c. PaintBuilder.build()      — walk 3
6. Returns Fragment::Svg
7. Display list builder →
   DisplayItems → WebRender GPU
────────────────────────────────────
Total: 3 walks, 1 pass, no serialization

Stateless Between Frames

The engine leaves no state between process() calls. On viewport resize or re-layout, the engine runs from scratch with the new viewport size.

Exception: The ReferenceRegistry could be cached if the DOM hasn't changed (future optimization).

🔌 Integration Point — make_fragments() in layout/replaced.rs
fn make_fragments(...) -> Vec<Fragment> {
    match &self.kind {
        // ... other cases (Image, Video, IFrame, Canvas) ...
        ReplacedContentKind::SVGElement { .. } => {
            // Build the styled subtree from DOM
            let styled_root = build_svg_subtree(node);

            // Run the engine — one synchronous call
            let result = SVG_ENGINE.process(
                &styled_root,
                ViewportSize { width, height },
                dpr,
            );

            match result {
                SvgEngineResult::Ok(display_list) => {
                    vec![Fragment::Svg(ArcRefCell::new(SvgFragment {
                        base,
                        display_list,
                    }))]
                }
                SvgEngineResult::Recoverable(display_list, _error) => {
                    // Paint partial output, log warning
                    vec![Fragment::Svg(ArcRefCell::new(SvgFragment {
                        base,
                        display_list,
                    }))]
                }
                SvgEngineResult::Fatal(error) => {
                    // Broken image icon
                    vec![Fragment::Image(broken_image_fragment)]
                }
            }
        }
    }
}

Section 2

Component Architecture

The engine has 5 components: SvgEngine (orchestrator), StyleResolver, LayoutEngine, PaintBuilder, and ReferenceRegistry. Each has a single responsibility and clear data flow.

⚙️ 2.1 SvgEngine — Orchestrator

The SvgEngine owns all sub-components and drives the 3-phase pipeline on every process() call. Created once when the layout thread initializes, reused across frames.

pub struct SvgEngine {
    styles: StyleResolver,
    layout: LayoutEngine,
    paint: PaintBuilder,
    registry: ReferenceRegistry,
    debug_trace: bool,
}

impl SvgEngine {
    pub fn process(
        &mut self,
        root: &SvgStyledNode,
        viewport: ViewportSize,
        dpr: Scale<f32, CSSPixel, DevicePixel>,
    ) -> SvgEngineResult<SvgDisplayList> {
        // Phase 1: Style resolution + registry population
        let mut inherit_state = InheritState::default();
        self.styles.resolve(root, &mut inherit_state, &mut self.registry)?;

        // Phase 2: Layout — transforms + bounding boxes
        let mut transform_stack = TransformStack::new();
        let vb_transform = self.layout.compute_viewbox_transform(viewport, root);
        transform_stack.push(vb_transform);
        self.layout.layout_tree(root, &mut transform_stack)?;
        transform_stack.pop();

        // Phase 3: Paint — generate display commands
        let mut commands = Vec::new();
        self.paint.build_tree(
            root,
            &self.styles.styles,
            &self.layout.layouts,
            &self.registry,
            &mut commands,
        )?;

        Ok(SvgDisplayList {
            commands,
            is_animating: false,
            viewport_rect: viewport.into(),
            intrinsic_size: root.intrinsic_size(),
        })
    }
}

🎨 2.2 StyleResolver — Property Extraction + Inheritance

Tree walk algorithm — top-down, depth-first. At each node:

resolve(node, inherit_state, registry):
  1. If node is <defs>:
       → Register all children in registry by id
       → Skip children (not rendered)
       → Return
  2. If node is a reference element (gradient, clipPath, etc.):
       → Parse and register in registry
       → Return (no rendering styles)
  3. For renderable/container elements:
     a. Extract fill from ComputedValues
        "red" → PaintServerValue::Solid(red)
        "url(#g1)" → PaintServerValue::Url("g1")
        "none" → PaintServerValue::None
     b. If no explicit fill → inherit from parent
        If no parent either → use SVG default (black)
     c. Extract stroke (default: none), stroke-width (1px),
        opacity (1.0), transform, visibility, etc.
     d. Extract reference URLs:
        clip-path: "url(#c)" → Some("c")
        mask: "url(#m)" → Some("m")
        filter: "url(#f)" → Some("f")
     e. Store ResolvedSvgStyles in self.styles[node]
     f. Update inherit_state, recurse to children
     g. Restore inherit_state (siblings don't inherit from each other)

InheritState — values that cascade from parent to child:

pub struct InheritState {
    pub fill: PaintServerValue,        // default: black
    pub stroke: PaintServerValue,      // default: none
    pub fill_opacity: f32,             // default: 1.0
    pub stroke_opacity: f32,           // default: 1.0
    pub fill_rule: FillRule,           // default: NonZero
    pub stroke_width: Length,          // default: 1px
    pub stroke_linecap: LineCap,       // default: Butt
    pub stroke_linejoin: LineJoin,     // default: Miter
    pub stroke_miterlimit: f32,        // default: 4.0
    pub font_family: FontFamily,       // default: Serif
    pub font_size: Length,             // default: 16px
    pub opacity: f32,                  // default: 1.0
    pub visibility: Visibility,        // default: Visible
}

📐 2.3 LayoutEngine — Geometry + Transforms

TransformStack — maintained during depth-first tree walk:

struct TransformStack {
    stack: Vec<AffineTransform>,
    current: AffineTransform,     // cached product of all transforms
}

impl TransformStack {
    fn push(&mut self, t: AffineTransform) {
        self.current = self.current.then(&t);
        self.stack.push(t);
    }
    fn pop(&mut self) {
        if let Some(t) = self.stack.pop() {
            self.current = AffineTransform::identity();
            for t in &self.stack { self.current = self.current.then(t); }
        }
    }
    fn current(&self) -> &AffineTransform { &self.current }
}

Layout tree walk — per-element algorithm:

layout_tree(node, transform_stack):
  1. Skip <defs> and reference elements (no layout needed)
  2. Parse element's transform attribute
  3. Push transform onto stack
  4. Compute local_bbox from element geometry:
     Rect(r)     → Rect(r.x, r.y, r.w, r.h)
     Circle(c)   → Rect(c.cx-c.r, c.cy-c.r, 2*r, 2*r)
     Path(p)     → compute_path_bbox(p.path_data)
     G           → union of children bboxes (post-order)
     Text(t)     → compute_text_bbox(t, font_metrics)
  5. viewport_bbox = transform_stack.current() ∘ local_bbox
  6. Store ElementLayout { local_bbox, viewport_bbox, transform }
  7. Recurse to children (depth-first)
  8. Pop transform_stack

viewBox mapping — the math:

fn compute_viewbox_transform(viewport, viewbox, par) -> AffineTransform {
    let scale_x = viewport.width / viewbox.width;
    let scale_y = viewport.height / viewbox.height;
    let uniform = match par.align {
        None → (scale_x, scale_y),
        _    → if meet { min(scale_x, scale_y) } else { max(scale_x, scale_y) }
    };
    let tx = match par.align_x { Min→0, Mid→(vp.w-vb.w*s)/2, Max→vp.w-vb.w*s };
    let ty = match par.align_y { Min→0, Mid→(vp.h-vb.h*s)/2, Max→vp.h-vb.h*s };
    AffineTransform::translate(tx, ty).then(&AffineTransform::scale(s, s))
}

Bounding box by element type:

ElementFormula
<rect>(x, y, width, height)
<circle>(cx-r, cy-r, 2r, 2r)
<ellipse>(cx-rx, cy-ry, 2rx, 2ry)
<line>(min(x1,x2), min(y1,y2), |dx|, |dy|)
<path>Walk segments, track min/max x,y (conservative: include control points)
<g>Union of all children's viewport_bbox (post-order)
<text>Sum of glyph advances × font metrics

Nested viewports: An <svg> inside SVG pushes a new viewport transform onto the stack with its own viewBox mapping, plus the (x, y) offset.

🖌️ 2.4 PaintBuilder — Display Command Generation

DisplayCommand — the engine's intermediate representation:

pub enum DisplayCommand {
    Fill { path: PathData, paint: ResolvedPaint, fill_rule: FillRule, opacity: f32 },
    Stroke { path: PathData, paint: ResolvedPaint, params: StrokeParams, opacity: f32 },
    Group { children: Vec<DisplayCommand>, transform: AffineTransform, opacity: f32 },
    ClipDefine { id: ClipId, paths: Vec<PathData>, fill_rule: FillRule },
    ClipApply { id: ClipId, children: Vec<DisplayCommand> },
    Mask { id: MaskId, content: Vec<DisplayCommand>, mask_content: Vec<DisplayCommand> },
    Filter { id: FilterId, primitives: Vec<FilterPrimitive>, children: Vec<DisplayCommand> },
    Text { position: Point2D<f32>, text: String, font: FontDescriptor, paint: ResolvedPaint },
    Image { data: ImageData, rect: Rect<f32> },
    Clear { rect: Rect<f32>, color: AbsoluteColor },
}

pub enum ResolvedPaint {
    None,
    Solid(AbsoluteColor),
    Gradient { start: Point2D, end: Point2D, stops: Vec<GradientStop>, spread: SpreadMethod },
    RadialGradient { center: Point2D, radius: f32, stops: Vec<GradientStop>, spread: SpreadMethod },
}

Per-element paint sequence — the exact order of operations:

build_tree(node, styles, layouts, registry, commands):
  1. Skip <defs> and reference elements (already registered)
  2. If style.display == none → skip
  3. Get style = styles[node], layout = layouts[node]

  4. // Start building commands
  5. let element_commands = Vec::new()
  6. let path = compute_path(node)
  7. let fill = resolve_paint(style.fill, layout.viewport_bbox, registry)
  8. let stroke = resolve_paint(style.stroke, layout.viewport_bbox, registry)

  9. if fill exists AND fill_opacity > 0:
       element_commands.push(Fill { path, fill, style.fill_rule,
                              fill_opacity * style.opacity })
  10. if stroke exists AND stroke_opacity > 0:
        element_commands.push(Stroke { path, stroke, style.stroke_params,
                                stroke_opacity * style.opacity })

  11. // Wrap in clip/mask/filter if needed (outermost first)
  12. if style.clip_path exists:
        element_commands = [ClipApply { id, children: element_commands }]
  13. if style.mask exists:
        element_commands = [Mask { id, content: element_commands, mask_content }]
  14. if style.filter exists:
        element_commands = [Filter { id, primitives, children: element_commands }]

  15. // Apply element transform + opacity
  16. if transform != identity OR opacity < 1.0:
        commands.push(Group { children: element_commands,
                              transform, opacity: style.opacity })
     else: commands.extend(element_commands)

Paint server resolution — how url(#g1) becomes a gradient:

fn resolve_paint(value, element_bbox, registry) -> ResolvedPaint {
    match value {
        None → ResolvedPaint::None
        Solid(c) → ResolvedPaint::Solid(c)
        Url(id) → match registry.get(id) {
            LinearGradient(g) => {
                let (start, end) = if g.coordinate_mode == ObjectBoundingBox {
                    // Map [0,1] coordinates to element's bbox
                    (Point2D::new(
                        bbox.min.x + g.x1 * bbox.width(),
                        bbox.min.y + g.y1 * bbox.height(),
                    ), Point2D::new(
                        bbox.min.x + g.x2 * bbox.width(),
                        bbox.min.y + g.y2 * bbox.height(),
                    ))
                } else {
                    // userSpaceOnUse — absolute coordinates
                    (Point2D::new(g.x1, g.y1), Point2D::new(g.x2, g.y2))
                };
                ResolvedPaint::Gradient { start, end, stops: g.stops, spread: g.spread }
            }
            _ → ResolvedPaint::None  // missing reference
        }
    }
}

Population strategy: During the style resolution pass, when the resolver encounters a <defs> element:

On <defs>: push special state "children go to registry"
  For each child:
    Parse element type + parameters
    Extract id attribute (key)
    Create ReferenceDefinition variant
    registry.register(id, definition)
    Do NOT render these children
Pop state → return to normal rendering

Deferred resolution: The registry stores definitions as structured data. The PaintBuilder resolves them only when needed (after bounding boxes are computed). This handles objectBoundingBox coordinate mode where the gradient's endpoints depend on the element's bounding box.
